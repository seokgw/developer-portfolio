04 / MCP SERVER & OPERATIONS

MCP 서버 구성과 인증 연결

AI 도구가 외부 기능을 호출할 수 있도록 MCP 서버를 연결하고, 서비스 기동 오류 복구부터 HTTPS·OAuth 인증 흐름까지 구성한 경험입니다.

Node.jsMCP / Streamable HTTPOAuth / PKCENginx / systemd

나의 역할: 기존 서버 점검·연결 복구 요청, 클라이언트 OAuth 승인 · AI 역할: 코드·설정 변경과 기술 검증. 세부 설정의 직접 수행 범위는 추가 확인이 필요합니다.

MCP 구성과 장애 해결 과정 보기

서비스가 시작되지 않은 원인

systemd 서비스에 지정된 실행·환경 파일 경로와 실제 배포 위치가 달라 서버가 기동하지 않았습니다. 배포 경로와 서비스 설정을 맞춘 뒤 기동·상태 확인·MCP 초기화 순서로 복구 결과를 점검했습니다.

인증된 요청을 전달하는 구조

MCP 클라이언트 → HTTPS / Nginx → OAuth 인증 게이트웨이 → MCP 서버로 연결했습니다. Google 로그인과 PKCE 기반 코드 교환을 거친 요청을 전달하고, 인증되지 않은 요청은 거부하도록 구성했습니다.

당시 확인한 결과

  • 서비스 기동과 health 응답, MCP initialize 및 도구 목록 조회
  • 미인증 요청의 401 응답과 인증 후 MCP 초기화의 HTTP 200 응답
  • 인증서 갱신 dry-run과 클라이언트 OAuth 로그인 성공 기록

과거 구축·검증 기록을 바탕으로 정리했습니다. 이번 포트폴리오 추가 작업에서는 운영 서버에 접속하거나 현재 상태를 재검증하지 않았습니다. 구현·설정·기술 검증은 AI 수행 범위이며, 직접 코딩한 성과로 표현하지 않습니다.
